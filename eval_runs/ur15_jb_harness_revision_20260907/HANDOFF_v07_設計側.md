## 1. この席が持っているもの、持っていないもの

| | |
|---|---|
| やること | 設計案の作成、試算、スクリプトの作成、記録、実行側への依頼文 |
| やらないこと | **採否の決定**（Rs）、**物理妥当性の判定**（VaultProtocol V12 の独立レビュー経路） |
| 持っていないもの | **Blender と native**。シーンは測れない |

**この席はシーンを測れない。** シーン由来の数字はすべて実行側の計測に由来する。
手元で確かめられるのは、コミット済み JSON の読み直しと、`bpy` を差し替えた合成試験と、
**コミット済みファイルだけで完結する検査**（`check_co_run_calibration.py` /
`check_fixed_set_mapped.py`）である。**この 2 つは自分で走らせること** — 実行側の報告から
数字を書き写すと、書き写し誤りがそのまま通る（訂正表 26）。
**測っていないものを測ったように書かないこと。** 訂正表の 14 番はそれで起きた。

## 2. 走らせる前に、何が変わるかを宣言する

**この席で唯一いちばん効いている習慣である。** 実行側に再実行を頼むときは、毎回その前に
「変わるのはここだけのはずだ」を具体的に書く。

```
変わるのは co_run の中身と method の2項目だけのはずです:
 - extent_m が消え、extent_lower_m / extent_upper_m になる
 - ...
それ以外が動いたら送ってください。
```

効く理由は 2 つある。

- **予測が外れたことが、実行側にも自分にも見える。** 一度「変わるのは crossings 側」と書いて、
  実際に動いたのは `cables[*].run_length_m` だった。自分の変更の影響範囲を把握していなかった
  ということで、予測を書いていなければ気づかないまま通していた。
- **実行側が葉ごとの突き合わせをして返してくれる。** 「予定外の変化 0 件」が返ってきて初めて、
  変更範囲が確定する。これを毎回もらっている。

**依頼文には必ず「見たいのはどれか」も書く。** 何が出たら結論が変わるのかを先に言う。

## 3. 器械は、既知の形で校正してから信じる

数字を出す前に、**答えが構成上わかっている図形**に同じ器械を当てる。合わなければ、
その出力は**注釈を付けずに取り下げる**。ここまでに取り下げたもの:

- **曲げ半径** — 真の半径が無限大の直線管が 0.149 m と出た。実在の曲げが取る範囲の中なので
  区別できない。報告項目ごと削除した。
- **3 mm の共走しきい値** — 中心線自身の揺れより細かい。器差を測っていた。
- **`extent_m` という単一の数** — 測定値と padding が混ざっていた。対に分けた。
  さらに、その片方を `extent_lower_m` と名付けたのが**過剰な主張**だった。歩幅より狭い谷は
  標本に見えないので下限ではない。`extent_sampled_m` に改名した（訂正表 24）。
  **名前が量より強いのも、取り下げるべき誤りである。**

**「およそ」を付けて残さない。** 残すと次の席が使う。

### 3.1 校正は、実行可能な検査として書く

`scripts/check_co_run_calibration.py` は、`bpy` を差し替えて Blender なしで走る。
**10 件**の場合を、測る前に答えを宣言する形で書いてある（現席で実走、exit 0）。

**これは自分の修正の欠陥を 2 件見つけた。** どちらも盤面では出ないものだった。

- 2 mm の隙間を「10 mm しきい値の境界」と誤判定（別の量を同じ定数で代用していた）
- 接近ゼロの組で例外を投げて落ちる（118 組の走査なら全体が止まっていた）

**検査を書いたら、欠陥をわざと戻して落ちることを確かめる。** 落ちない検査に意味はない。

## 4. 実行側との関係

### 4.1 直通がある（2026-09-12 に判明。訂正表 33）

**旧記載「直通はない。すべて利用者が中継する」は誤りだった。** それは前任者がクラウド側に
いたための制約で、この席の性質ではない。**同一マシンに座っていれば直接やり取りできる。**

- `ListAgents` で相手を探す。名前は `isaaclab-XX` の形で役割を示さないので、**同定は実測で行う**。
  現在の実行側は **`isaaclab-70`**（session `cdee2083-a65b-4560-8d7d-6a5313ffeae8`）。根拠は 3 つ
  独立に取った — その記録に v07c 走査の参照が 368 件ある / 最終更新 09:00:33 が commit
  `9cf3b080e1` の時刻と一致する / 利用者の画面でそのペインが 09:00 に終わっている。
  **`~/.claude/sessions/*.json` が pid → 名前 → session → 作業ディレクトリを持っている。**
- `SendMessage` で送る。`notify_when_idle` を付けると相手が手空きになったとき 1 回だけ知らせが来る。
  **ポーリングはしない。**
- **座り直すたびに同定し直すこと。** 名前は役割を示さないので、記憶した対応表を信用しない。

**依頼文の作り方は変わらない。** 手順・予測・見たい点を 1 通に収める。直通でも、相手が
そのまま実行できる形であることに変わりはない。往復は `audit/op030_v07c_request_NN_*.json` に
1 往復 1 ファイルで残す（予測を先に固定するため。§2 の習慣が会話にしか残らないのを塞いだ）。

**中継が要る場合もまだある。** 相手が別マシン・クラウドにいるときは旧記載どおりになる。

### 4.2 実行側の推測を、確定として書かない

訂正表 14 番（`p04` の二度目の取り違え）はこれで起きた。実行側が推測として提示したものを、
次の文書で確定として記録した。**「推測」と付いていたら、そのまま「推測」と書き写す。**

### 4.3 実行側の計測が文書と食い違ったら、計測が正しい

訂正表 36 件のうち大半はこの席の誤りで、実行側の計測が覆した。**辻褄を合わせにいかない。**
**この席自身が書いた検査も例外ではない** — 33〜36 は現席が自分の前任と自分自身に対して足したものである。

### 4.4 独立検証は、食い違ったときがいちばん価値がある

直近の例。実行側の独立測定は「10 mm 共走は連続 1 区間」、こちらの器械は「4 区間」。
**extent は合うが形が合わない。** ここを「だいたい合っている」で流さずに原因を詰めたら、
しきい値と中心線の揺れが同じ大きさだという器械側の限界が出た。

## 7. 使っている定数の出どころ

`scripts/probe_op030_v07c_routing_survey.py` の定数は、どれも**選んだのではなく測って決めた**。
変えるときは同じことをする。

| 定数 | 値 | 根拠 |
|---|---|---|
| `STEP_M` | 0.030 | 0.012 は密な直線管を 13% 水増しした。0.030 で 5 形状が 1.3% 以内 |
| `TERMINAL_TRIM_M` | 0.150 | 端の取り付け部は設計上の接触。そこを測ると経路の隙間が出ない |
| `CO_RUN_LIMITS_M` | 0.010 / 0.030 / 0.056 | 0.056 は 1 直径。3 mm は中心線の揺れより細かく退役 |
| `CENTRE_LINE_NOISE_M` | 0.010 | 意味のある最小しきい値 |
| `CENTRE_LINE_GAP_UNCERTAINTY_M` | 0.004 | **上とは別の量。** 太さの超過 0.004 から導出（訂正表 23）。⚠ **裏づけとしていた実行側の境界実測は、器械の出力と一致していない**（§11.5-f）。うち「2.1 mm」は実行側が取り下げた。導出そのものは太さから来るので立つが、**独立の裏づけは現在ない** |
| `PLACEMENT_TOLERANCE_M` | 1e-5 | Blender の行列は単精度。この座標で 1 段 2.4e-7 m |

## 8. 引き継ぎにあたっての注意

**訂正表を仕様書より先に読むよう指定した理由。**

この体制の品質は、2 つの席が**別々に間違える**ことで保たれている。訂正表 36 件の大半は
この席の誤りで、実行側の計測が覆した。**新しい席が私の文書を丸ごと信用すると、私の思い込みごと
引き継ぐことになり、相互検証が効かなくなる。**

したがって、

- **訂正表は「この席がどう間違えてきたか」の記録として読む。** 同じ形の誤りを繰り返さないため。
- **争点になった数字は、文書を信じずに JSON から引き直す。** 出典は本文に書いてある。
- **この文書自体も疑ってよい。** 誤りが見つかったら訂正表に足す。消さない。

**引き継げないものが 1 つある。** 実行側との間で積み上がった、どこを疑えばよいかの勘である。
これは文章にならない。代わりに §2 の「宣言してから走らせる」を機械的に守れば、
外したことがその場で見える。
