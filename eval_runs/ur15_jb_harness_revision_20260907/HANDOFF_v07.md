## 0. 分担と作法（2026-09-12）

**分担そのものは変えない。** 座る者が替わっても役割の線は同じである。
案を書く側の席を交代する場合は **`HANDOFF_v07_設計側.md`** を読むこと。本書に書いていない
「この席の動かし方」と、交代時点で宙に浮いていることをそこにまとめてある。

| 役割 | 担当 |
|---|---|
| 設計案の作成、試算、スクリプトの作成、記録 | 遠隔セッション |
| 実行、計測、結果の報告 | Blender と native を持つセッション |
| **採否の決定** | **Rs** |
| **物理妥当性の判定** | **VaultProtocol V12 の独立レビュー経路** |

案を書く側も動かす側も、**採否を決める権限は持たない**。

### 決めてよいこと、決めてはいけないこと

**設計は Rs の裁定事項である。** 裁定済みは §8、未確定は §9 にある。**未確定を自分で決めない。**
必要なら測って選択肢と数字を揃え、裁定に上げる。受入基準を発明しない。物理妥当性の判定を出さない
（判定は VaultProtocol V12 の独立レビュー経路による）。

決めてよいのは**測り方と作り方**である。どの検査を書くか、どの順で走らせるか、どこまで検証するか。

### 作業の作法 — ここまでの失敗から来た規則

1. **推定で書かない。** 文書の数値は計測ファイルに由来させ、出典のファイル名を添える。
2. **推測と確定を混ぜない。** 「推測」と付いた観察を、次の文書で確定として書かない。
   `p04` の取り違えはこれで起きた（推測として提示されたものを確定として記録した）。
3. **シーン構造から選択を再現しようとしない。** v06 は選択を**ファイルから読んで**いた。
   作業1で3回続けて外した原因はこれ一つである（§5）。記録されたファイルを読む。
4. **判定は2段階。箱で候補を出し、三角形で決める。** 箱は干渉の**上界**であって干渉ではない。
   **閾値を前段フィルタにしない。** 「50 mm 超の重なりだけ三角形に回す」は浅い接触を永久に
   隠す。候補は「隙間が閾値未満（重なり含む）」で取る。
5. **三角形交差は完全内包を検出しない。** 箱の包含判定を併用し、疑わしい組は光線で確かめる。
6. **probe は読み取り専用。** native を保存しない。前後で world 行列を比較して assert する。
7. **結論が覆ったら訂正表に書く。** 何を撤回したか、なぜ誤ったかを明記する。消さない。
8. **失敗した検査結果も残す。** 使わない旧版には「使わない」と書く。

### 相互検証がこの作業の主要な品質手段である

**2セッション体制は双方の誤りを実際に捕まえている。分担を分けている理由がこれである。**

訂正表 58 件のうち大半は案を書く側の誤りで、いずれも**実行側の計測**が覆した（鏡映式のバグ、
「C は補修不要」、脚長 687、固定側照合の空振り、「OP020 は当たらない」、`p04` の二度の取り違え、
箱判定の前段フィルタ、掃引のグルーピングと名前ずれ）。逆に `p04` を床板とする推測は、実行側
自身の再計測が覆した。

したがって次を守る。

- **実行側は、受け取ったスクリプトと説明を疑ってよい。** 実測が文書と食い違ったら、実測が正しい。
  食い違いはそのまま報告する。辻褄を合わせない。
- **案を書く側は、実行側の推測を確定として書かない。** `p04` の取り違えはこれで起きた。
- **全主張を commit 済み JSON に紐づける。** 手元にしかない計算を結論の根拠にしない。
- **独立検証サブエージェント**を要所で回す。
- **疑う場所を決めておく。** 「箱で当たった」「名前からそう見える」「前回そう書いた」の3つは、
  これまで全部間違いの入口だった。

v06 の native `e65bef60…`、B bank `41b353e2…`、ZIP `1c66b66a…` を上書きしない。
**ZIP は現在ゴミ箱にある。Downloads へ戻すこと。**

### `missing` と `closure=False` はエンドエフェクタの違いである

異常ではない。v06 の工程・部品確認書が、セルごとに工具構成が違うと記録している。

| C | **M6 直形締付工具を常設** | **M14 直形締付工具を常設** |

実測値がこれと厳密に一致する。

| | B に無い（missing） | 自前で持つ（closure の extra） |
|---|---|---|
| A | 左手フィンガ **21** | M4 ドライバ **27** |

### したがって選択規則を改める

葉の名前で対応付けるのではなく、**根を対応付けてそのセルで閉包を取る**。

```
1. 104 本の根をセルへ対応付ける（A・C とも 85 本が対応）
2. そのセルで descendants() を取る
3. その閉包がそのセルの装備一式
```

こうすればそのセル自身の工具が自動的に入り、B の工具は入らない。現在の `closure_brings_extra` がその工具であり、捨てずに使う。

#### 4 区間という形は実体ではない。境界の不確かさを出すようにした

から導いた — 真の軸から r ずれた中心線は断面を 2r 太く読ませるので、太さの超過 0.004 m は
1 本あたり約 0.002 m、2 本の間の隙間で約 **0.004 m** を意味する（`CENTRE_LINE_GAP_UNCERTAINTY_M`）。

## 6. 背景の要点

### 試算の根拠

作業定義の秒数と保存 bank のフレーム数から導いた。作業定義合計 250.0 秒に対し A bank 238.8 秒のため、**換算係数 0.955** を一律適用。

**すべて保存アニメーション時間の相対比較であり、実機タクトではない。** 映像用の関節上限 1.2 rad/s（実測最大 0.981）下の値。

### 効いている事実

- **A の 67% はボルト作業**。支持部のハンドリングは 9.4 秒、M4 取得 31.7 秒＋締結 39.2 秒。
- **工程順序は厳密**（支持部設置 → ケーブル設置 → 端子締結）。各 ST の担当は順序付き作業列の連続区間でなければならない。
- **案④で律速が ST2 へ移る**。ST1 60.4 秒 < ST2 63.1 秒。E4（復帰最大 63.1 秒）も ST2 で、**律速と最大リスクが重なる**。
- **鏡映変換** `M(y) = diag(−1,−1,1) ＋ Y 方向 2y`。行列式 +1 の 180° 剛体回転で FK が保たれ、自己逆変換。ST1 は −3.4、ST2 は +1.2、ST3 は +5.8。
- **複製機構 `duplicate_set()` が既存**（`op030_split_layout.py:84`）。`obj.copy()` で mesh 共有、命名は `prefix + "__" + name`、`split_source_name` を刻む。作業3で再利用できる。
- **セルごとに工具構成が違う**（§2）。複製は各セル自身の工具を運ぶ。
