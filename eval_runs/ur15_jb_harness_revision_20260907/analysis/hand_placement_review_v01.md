- 対向2本指の位置、回り止め・端当て・肩受けを、8つの縮尺なしの模式図で示した。
- 開放方向と工具方向の表示を切り替えられる。矢印は方向だけで、連続軌道ではない。
- F01〜F07の写真枠は前段と同一。F08〜F10とP01〜P03は写真の把持位置を未特定として枠を描かない。
- OP040は旧番号の参照に残し、今回の実物接続対象はB/Cで確認する。D04や追加6本を割り付けない。
- ケーブル用F05/F06から、保存済みT050の3Dページへ移動できる。

模式図の形状・穴の数と位置は、実物部品の加工寸法や許容接触面を示していない。
公開写真の枠も部材の位置例であり、そこを全面クランプしてよいと指定したものではない。

## ケーブル用の3D表示

`ケーブル保持3D_v01.html` は元の20実体メッシュと4保存状態をそのまま使用する。
ドラッグで回転、ホイールで拡大。側面・正面・上面・斜め表示、黒い機構と参考部品の表示を切り替えられる。

- T050、時計回り15°、傾斜前40 mm後退、黒被覆と根元保持を継承。
- 元メッシュと全状態の行列を変えず、ガイド用円筒は表示しない。
- 新しい工具の外形や干渉数値は足していない。
- 状態間の補間、アーム動作、ケーブル物理変形、把持性能の判定はしていない。

取付部の版を2019 TMへ置換したり、旧F06の金属端子クランプへ戻したりしていない。
被覆の軸方向滑り・軸回り回転・端子との相対ずれ、工具ノーズ一式との関係は確認が残る。

## 再生成

作業ツリー、または同梱コードを展開したディレクトリで、Python標準ライブラリのみで実行できる。
リポジトリでは `./isaaclab.sh -p` を使う。

```bash
./isaaclab.sh -p \
  eval_runs/ur15_jb_harness_revision_20260907/scripts/build_hand_placement_review_v01.py \
  --output_directory /tmp/hand_placement_review_new
```

出力ディレクトリが既にあれば停止する。
現在の手先仮仕様・写真対応・デフォルト設定のSHAを照合し、T050は既存選択器で5入力のSHAを確認する。
元の15°パッケージが別の場所にある場合は `--source_directory` で指定する。

同梱のGLBだけで再生成はできない。保存済みの完全な15°パッケージ
`/home/rlrk/Downloads/THREAD_フィンガ15度傾斜_v01_20260914/` が入力として必要。
この確認資料にはその大きいnativeや旧比較版を複製していない。

## 根拠と確認の境界

- 手先の仮仕様: `data/hand_provisional_spec_v01.json`、commit `4dabc263cdf247b8bd8ffe788b8f081e60b64498`。
- 写真位置: `data/hand_target_contacts_v02.json` の座標とSHAを維持。旧把持方式の文章は新表示へ取り込まない。
- T050: `data/hand_working_default_v01.json` と `prepare_hand_working_default_v01.py` を再利用。
- WebGL表示: 既存の `hand_clockwise_tilt_viewer_v01.html` の行列適用・描画方式を再利用。
- 写真は[Ampereの公開製品資料](https://help.ampereev.com/hc/en-us/articles/31292470232087-High-Voltage-Junction-Box-HVJB-5-400)に対応する。
  把持図は本作業の模式図で、メーカー指定の把持方法ではない。
- 交換指先方式は[Robotiqの公式資料](https://assets.robotiq.com/website-assets/support_documents/document/online/2F-85_2F-140_TM_InstructionManual_HTML5_20190503.zip/2F-85_2F-140_TM_InstructionManual_HTML5/Content/6.%20Specifications.htm)と既存の仮仕様を継承する。
  新たな材料・荷重の仕様を今回追加したものではない。

確認対象は参照対応、写真の画素範囲、保存メッシュと行列の一致、およびブラウザー表示。
これは全ライン実寸モデルへの配置完了や、実物の安定把持・締結品質の実証ではない。
正式な物理妥当性判定はVaultProtocol V12の独立レビュー経路による。
