# D40 根元支持部の一体化 v01

2026-09-14。根拠は前版R025/R050の保存座標、今回の生成器・Blender出力、元取付面の計測記録。
別部品だった青い根元支持部を青い取付板・梁と一体にした比較形状を作成した。
パッドの接合方法や実材料の強度を採用・判定したものではない。

## 形状の変更と維持

40 mm後退を初期値とするユーザー指定を維持。前方の端子側輪郭、根元ケーブル用パッド、
参考ワーク、黒い元機構の頂点・面・色と、残る全オブジェクトの4保存姿勢・関節値を照合した。
元の左右各1個の青い支持部をキャリアに統合し、モデルのメッシュ数は22から20になった。
上押さえ、別の駆動、腕軌道は追加していない。

| 比較形状 | 前版 | 上端の逃げ | 一体キャリア：片側の頂点／三角形 | 接続成分 |
|---|---|---:|---:|---:|
| J025 | R025 | 0.25 mm | 562／1,128 | 左右各1 |
| J050 | R050 | 0.50 mm | 562／1,128 | 左右各1 |

両案とも閉鎖edge・面向き一致、厳密なゼロ面積面0枚、Euler数−2を記録した。
これは保存メッシュの接続の観測であり、加工可能性や強度の証明ではない。
0.25 / 0.5 mmのいずれかを採用したとは扱わない。

構成は前段と同じ公称14×31×4 mm取付板、4×6 mm梁、1.5×8×10.3 mm前部と根元支持部。
取付面の共通座標で再構成し、根元支持部を板内部へ演算用に0.5 mm重ねて結合した。
この重なりは追加突起や組立公差の指定ではない。パッドの受け面は元の平面へ戻した。
青緑のパッド自体は元の別メッシュを保持しており、接着・成形接合などは未選定。

## 穴とパッド受け面

元の3穴軸を再利用し、青い部品に公称φ3 mm、64分割の滑らかな穴を設けた。
黒い元末節のねじ用φ3.4 mm穴、16 mmピッチ、中央φ3 mm穴は変更していない。
根元支持部が覆う側の穴は取付面から4 mmまでの空間を保持し、その奥に支持部を残した。
ここでは穴の役割名`screw_upper`を使用しているが、保持姿勢では根元パッド高さにある穴を指す。
もう1本のねじ穴と位置決め穴の中心軸は、取付面から20 mmの観測範囲で一体部品の面に当たらなかった。

| 観測 | −X側 | ＋X側 |
|---|---:|---:|
| 根元側：元取付面から最初の穴底 | 4.000000 mm | 4.000000 mm |
| 穴底〜元パッド座面、法線方向の投影厚さ範囲 | 2.998731〜2.999175 mm | 2.998733〜2.999173 mm |
| 元座面9点と新支持面の最大距離 | 2.143×10⁻¹⁰ m | 2.215×10⁻¹⁰ m |
| 元穴の面内座標を新0/2/4 mm断面へ投影した点の最大距離 | 2.735×10⁻⁹ m以下 | 2.735×10⁻⁹ m以下 |

両案で同じ値。座面は4隅・中央・各隅と中央の中点を観測した。穴は各128点の面内座標を
3深さで観測しており、穴ごと384点。ねじ山はモデル化していない。
穴の深さをねじの有効かかり量とみなさず、約3 mmを必要強度から決めた板厚とも扱わない。
ねじ長さ、ねじ底隙間、材料、接合、把持力、製作公差は未選定のまま。

**青いキャリアの全頂点が不変なのではない。** 元の梁は取付面の座標とわずかに傾いていた。
再構成により元の根元側穴縁から新表面まで最大1.069334×10⁻⁶ mの実形状差が生じた。
元外面の頂点・三角形重心各側1,223点では最大1.352460×10⁻⁶ m／1.372446×10⁻⁶ m。
新支持部の内部となる147点はこの外面比較から分け、除外数を記録した。
これは有限点の距離であって形状全体のHausdorff距離ではない。
元穴縁の全3D座標の不変と、軸・径の面内対応を区別して記録している。

## 工具空間と片側交換の標本

同じ元取付面の外側50 mm帯で、元2ねじの比較用工具軸を4姿勢・左右で観測した。
根元パッドはこの外側帯に現れなかった。六角二面幅2 mmの外接円と帯内表面までの半径差は
約0.34349 mm。工具全体や製作ばらつきを含むアクセス判定ではない。

締結工具側は下側・上側・全体のZ帯を分けた既存観測器を再利用した。
近接姿勢の上側帯では元の黒い機構までの最小投影半径28.5 mmを維持。
下側帯は青い部品まで約12.3682 mmで、上側の値を工具全長へ拡張していない。
値は`fastening_tool_surface_observations`、ねじ側は`outer_screw_tool_axes`に全姿勢分を収録。

開放姿勢から片側の指先一式を内向きへ0〜12 mm、0.5 mm刻みで計算した。
1標本は移動3部品（キャリア、端子側輪郭、根元パッド）×固定13部品＝39組。
2形状×2側×25標本＝3,900組。sceneのworld行列を再代入せず、派生頂点だけを移動させた。

| 比較形状 | −X側：0.5〜12 mmの24標本で面交差検出 | ＋X側：同左 | 0 mmの記録 |
|---|---:|---:|---|
| J025 | 0 | 0 | 左右各1組、キャリア／同じ側の元末節 |
| J050 | 0 | 0 | 同上 |

0 mmの三角形組数は左右62／65。前版と三角形分割が異なるため、組数減少を侵入量改善と解釈しない。
参考ワーク、ねじ頭と位置決めピンは交換標本に含まない。三角形表面の有限標本であり、
連続経路・固体包含・負荷時の変形・実機の交換可否を判定していない。

## 途中で停止した処理と修正

1. 旧キャリアへ直接Boolean結合して穴を再加工した初回は、左右でゼロ面積面36／30、
   接続成分7／5、閉じていないedgeが発生し、出力前にassert停止した。
   単純な頂点統合でも閉じなかった。ログと未修復の出力を保存した。
   既存`_box_union`で共通座標の公称primitiveを先に結合し、穴を一度だけ加工する方式へ変更した。
2. 次の出力は閉鎖1成分となったが、旧穴縁の全3D不変を求めたassertで停止した。
   前述の約1.069 µm差は実形状差であり、その値を隠さず記録した。
   穴の面内対応を定義済みの断面で測る欄を分けた。比較値1×10⁻⁷ mを増やしていない。
3. 同じ出力への距離計算で、左座面端の1点が0.133 µm離れて見えた。
   使用中のtrimeshは内積と固定epsilonで三角形の辺領域を分類するため、m単位ではこの端付近が
   辺へ丸められていた。同一座標をmm換算して計算し、結果をmへ戻すことで解消した。
   パッド座面もライブラリepsilonも動かしていない。最大値は約2.143×10⁻¹⁰ mとなった。

旧失敗出力を補修して使ったのではなく、元R025/R050入力から最終形状を生成した。
各再試行前にVault prior-art gateと具体的な変更点を記録した。

## 保存ファイルと再利用の根拠

Blenderは2形状×4姿勢の8シーン、各20メッシュ。world行列・頂点/面SHA・個数・表示状態は
保存読戻しで一致し、観測計算の前後も不変。各GLBは20メッシュで再読込でき、全体境界差は
最大1.491×10⁻⁹ m。境界だけで局所の保存を保証せず、元の不変要素も別途照合した。

PC／スマートフォン相当の画面で各30操作を行い、形状・4姿勢・左右の分解方向・表示切替・
数値対応・有限座標・WebGL描画・ローカルリンク・横はみ出しを確認した。画面を目視点検した。
配布用にコピーしたコード・設定・入力を別の出力先で実行し、形状JSONと両GLBのSHA、
全計測値が一致した。nativeは各実行で読戻し一致、記録も日時・BlenderバイナリSHA以外は一致。
これは独立した物理レビューではなく、同じコードからの再生成確認である。

元入力SHAは`21557cf3a3a39dc5b992c8d3897a3ab89f21cc57d35ca3124e56a5763d79cab5`。
実行前後で照合し、元入力・v06を保存していない。
取付面計測、直方体結合、GLB出力、静止scene構築、BVH、工具帯観測を既存モジュールから再利用した。
既存細分メッシュの再Booleanが破綻したため、同じ公称primitiveからの再構成を必要とした。

公式取付基準は保持している旧モデルと対応する
[Robotiq 2018年版取扱説明書 p131](https://assets.robotiq.com/website-assets/support_archives/document_en/2F-85_2F-140_Instruction_Manual_PDF_20181130.pdf#page=131)。
異なる2019 TMの中央M5図と混用しない。保存PDFのSHAを再照合した。
[Robotiqのカスタム指先設計資料](https://blog.robotiq.com/how-to-design-custom-fingertips-for-your-application)
も再確認した。指の延長に伴う根元モーメント、相手部品、把持後の作業・取出し空間は別途評価を要する。
参考モデルのKlauke 6R6圧着前端子とφ14線を実Ampere採用部品として扱わない。

## 再生成

配布フォルダを作業ディレクトリとして、既存のNumPy／trimesh環境とBlender 4.5を使用する。
IsaacLab内ではPython呼出しに`./isaaclab.sh -p`を使う。`NEW_OUTPUT`は未存在の出力先を指定する。

```bash
python scripts/build_hand_support_integration_v01.py \
  --source inputs/hand_mount_relief_meshes_v01.json \
  --config data/hand_support_integration_v01.json \
  --blender /path/to/blender --directory NEW_OUTPUT
blender --background --python-exit-code 1 \
  --python scripts/save_hand_support_integration_v01.py -- --directory NEW_OUTPUT
cp 根元支持部の一体化_v01.md NEW_OUTPUT/
```

`hand_support_integration_meshes_v01.json`に2形状と4姿勢、`*_observations_v01.json`に穴・座面・工具帯、
`*_native_v01.json`に標本全文と保存読戻し、`audit/`に実行・停止・表示・再生成の記録を収録する。
`.blend`とJ025/J050の`.glb`は静止形状。3Dページから形状、4姿勢、片側の分解表示を切り替えられる。

パッド接合・材質・力・ねじ仕様は未選定。腕軌道と動画制作は停止中。
本資料は補助的な幾何観測であり、正式な物理妥当性の判定はVaultProtocol V12の独立レビュー経路による。
