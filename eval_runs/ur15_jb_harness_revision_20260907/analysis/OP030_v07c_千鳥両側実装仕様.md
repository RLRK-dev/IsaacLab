## 2. 鏡映変換の一般形

v06 の `build_op030_stagger_static_v06.py` が使った変換を一般化する。**コンベア中心を挟んで Y = y の ST を左右反転する変換は**

```
M(y) = [[-1,  0, 0, 0  ],
        [ 0, -1, 0, 2y ],
        [ 0,  0, 1, 0  ],
        [ 0,  0, 0, 1  ]]
```

- 行列式 +1 の Z 軸まわり 180° 剛体回転。**鏡映ではないため、腕・関節・指・カメラの形状と FK がそのまま保たれる。** v06 で実証済み。
- 自己逆変換（M(y)∘M(y) = I）。左→右も右→左も同じ行列で済む。
- 点 (x, y) を (−x, 2y − x の Y 成分) へ写す。すなわち **(x, y) → (−x, 2y₀ − y)**。セル基準は中心線上にあるため Y が不変に見えるが、供給器のように中心線から外れた点は Y も動く。

各 ST の Y：ST1 = −1.700、ST2 = +0.600、ST3 = +2.900。ST 間隔 2.300 m。

**M(y) は Z を変えない。** 床面基準が揃っていない部材は、鏡映しても揃わないまま複写される（§7.2）。

### 3.1 接触しているのはケーブルである（2026-09-12 確定）

**`p04` は制御盤の部品でも床板でもない。** 形状計測による:

- 台座の最下部 `p00` は床の高さ（Z −0.04〜0.03）にあり、`p04` の上に立っていない
- `p04` の最上部の上向き面は外接箱床面積の 0.3% で、台座の真上にも真下にも面が無い
- `p04` は太さ約 56 mm の1本のつながった筋。盤の側面 Z 0.19 付近から床へ下り、床上を約 1 m
  進んで輪を描いて上がり、台座 `p05` で終わる

**`p04` は盤からロボット台座へ至るケーブルである。** したがって盤どうしの接触 2 件は
**ケーブルどうしの交差**であり、据付部材の取り合いでも運動の問題でもない。両端が固定されて
いるので盤とは一緒に動かないが、**経路は変えられる**。作業4（各セルの配線・空圧の引き直し）で解く。

⚠ **現行の実接触は 2 件ではなく 3 件、ほかに隙間ゼロが 2 件ある**（`audit/op030_v07c_mesh_contact.json`
現行 `56e373e9…`）。候補条件を「隙間 50 mm 未満」に直したあとに出たもので、A のケーブルが
`OP020_direct_mating_station_foot1.33_-2.23` とも交差し（三角形 36 組）、C の M6 供給器の脚 2 本が
OP040 の台座端面に隙間なく載っている（2.5e-7 / 3.8e-7 m）。**内訳は HANDOFF §4「現時点の実接触」が正。**

**盤本体（`p00`/`p01`/`p03`）は鏡映位置のままでよい。** 面で確かめた最短距離は自セルのケーブル
0.067 m、OP040 のケーブル 0.102 m、stocker_04 0.127 m、Split_bay 0.748 m 以上で、**どの面とも
交差していない**。掃引が「空き無し」と出るのは、自セルのケーブル（盤に付いている）と Split_bay
の過大な箱が相手に入るためで、実体の制約ではない。

**占有箱の Y は 2.41 m で、ST 間隔 2.3 m より長い。** 片端が制御盤、反対端がロボットの腕

制御盤の内寄せと腕の待機姿勢にある。

**占有箱の下端 Z = −8.085 m は部品1個による。** `source_0690_m0117_p00`（`station_hardware_03`）が
床の 8 m 下にある。除けば下端はロボット架台の底 −0.040 m。判定は部材ごとの箱で行うため衝突数への
影響は無いが、**床下 8 m に設備部品があること自体はモデルの異常**であり、複製すれば 3 個に増える。
扱いは制御盤本体の浮きと同じ（記録し、是正は裁定）。

### 3.2 S2L は v06 の B から作る（2026-09-12 確定）

**床は一様である。** `audit/op030_v07c_floor_contact_probe.json` が、最大面積の平面メッシュとして `source_0001_m0001_p00` を独立に導出した。面積 **1575.6 m²**（X −13〜+13、Y −22〜+38.6）、上面 Z は単一値 **−0.033**。場所依存はない。

## 4. 移設と複製の違い

v06 は roots の parent を新しい EMPTY へ付け替える「**移設**」だった。v07c は「**複製**」であり、次の差分がある。

1. **名前空間**。複製では UID を保てないため、新しい接頭辞を与える。**2026-09-12 裁定により `OP030_S1R__*`（二重アンダースコア）を採用**し、`duplicate_set` は変更しない。2026-09-11 の単一アンダースコア裁定は差し替えた。v06 の既存名は改名しない。
2. **形状データの共有**。`obj.copy()` のみとし、mesh データは複製元と共有する（2026-09-11 裁定）。片側だけ形状を変える必要が生じた時点で `obj.data.copy()` へ切り替える。**ただし §7.2 の補修は複製前に元へ入れる**ため、共有のままで補修が両側へ伝わる。
3. **オブジェクト数**。B の移設対象は roots 104 / moved 420。3 体複製すると **約 1,260 オブジェクトが増える**。現行 9,570 に対して 13% 増。

## 7. 空圧と床支持

### 7.1 空圧

v06 では空圧ドロップ `Split_bay_1__source_0782_m0209_p00..03` が新しい旋回経路と接触し、主管に沿って世界 Y = 0.45 → −0.33 m へ 780 mm 移設した。枝管は右主管の X1.42 / Z2.62 m へ接続している。

### 7.3 配線の引き直し — 問題の計測された姿（2026-09-12）

**⛔ ここでは離す量も向きも決めない。** 曲げ半径・支持ピッチ・他系統との必要離隔は実物のケーブルの
性質でモデルから測れず、裁定 2 で Rs 事項になっている（`HANDOFF_v07.md` §11.6）。本節が書くのは
**測れている姿だけ**である。

**離すべきは 2 組。どちらも「点で交わる」のではなく並走している。**

| 組 | Y の重なり | 1直径（56 mm）以内の共走 | 軸間 | 交差角 |

### 7.3 補修の要否（結論）

| セル | 供給器・供給台 | 制御盤 下部板 | 制御盤 本体 p00 / p04 |
|---|---|---|---|
| **A** | **足 33 mm 下げ＋脚 33 mm 延長**（×2） | **30→68 mm 延長** | 未処理（全セル共通） |
| **B** | 不要（v06 済） | 不要（v06 済） | 未処理（全セル共通） |
| **C** | 不要（既に接地） | **30→68 mm 延長** | 未処理（全セル共通） |

**C は補修が要る。** 2026-09-11 に「C 側は補修不要」と書いたのは誤りで、撤回する。当時の検査はオブジェクト全体の AABB で床候補を絞っており、制御盤を一度も測っていなかった。

**A の脚の補修後の長さは 667 mm である。** 建造規則（`build_op030_split_v03.py` の `feeder_stand`）は
脚の上面を供給器台の高さで決め、下面を床の上の足に載せる。A の脚は 634 mm で上面 0.648、C の脚は
654 mm で上面 0.668。C は既に足 33 mm 下げ・脚 33 mm 延長を受けて 687 mm になっている。A に同じ
補修を入れれば 634＋33 = **667 mm**、上面は 0.648 のまま動かない。A と C の 20 mm 差は供給器台の
据付高さの差であり、床補修で埋める対象ではない。

補修は **複製前に複製元へ入れる**。形状データを共有する方針（§4-2）のため、元を直せば複製先にも伝わる。手法は `build_op030_stagger_supported_static_v06.py` の `extend_lower` と足の平行移動をそのまま使う。

筐体本体 p00 / p04 の扱いは Rs 裁定事項とする（§10.2）。v07c の範囲を全セルの是正へ広げるか、現状を維持して記録にとどめるか。
