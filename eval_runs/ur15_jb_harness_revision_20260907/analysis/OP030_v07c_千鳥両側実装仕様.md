# OP030 v07c 千鳥両側6セル 実装仕様（案②）

作成: 2026-09-11。最終更新: 2026-09-11（床面基準の食い違いを反映）。親文書: `analysis/OP030_v07_刷新仕様案.md` 案②、`analysis/OP030_v07b_再分割詳細仕様.md` §7。

本書は**実装手順の提案であり設計決定ではない**。数値は保存動作時間の相対比較であり、実機タクトではない。正式な物理妥当性判定ではない。現行 v06（native `e65bef60…`）は上書きせず、v07c として新規に作る。

## 1. 目標

各 ST の反対側にセルを増設し、6 セルにする。**ST の数と担当は現行 v06 のまま**、ライン長も変えない。

| ST | 時間（秒） | 備考 |
|---|---|---|
| ST1 支持部 | **111.7** | 2.5（引出し）＋105.7（支持部1個）＋3.5（戻し・完了） |
| ST2 ケーブル | 63.1〜80.9 | 完全並列なら 63.1、近接区間を逐次にすると 80.9 |
| ST3 端子締結 | 36.1 | |

律速は ST1 の 111.7 秒。タクト 120.7 秒、29.8個/h、現行比 **×2.05**。ST2 の干渉問題はこの段階では結果に影響しない（v07b §5.3）。

## 2. 鏡映変換の一般形

v06 の `build_op030_stagger_static_v06.py` が使った変換を一般化する。**コンベア中心を挟んで Y = y の ST を左右反転する変換は**

```
M(y) = [[-1,  0, 0, 0  ],
        [ 0, -1, 0, 2y ],
        [ 0,  0, 1, 0  ],
        [ 0,  0, 0, 1  ]]
```

- 行列式 +1 の Z 軸まわり 180° 剛体回転。**鏡映ではないため、腕・関節・指・カメラの形状と FK がそのまま保たれる。** v06 で実証済み。
- 自己逆変換（M(y)∘M(y) = I）。左→右も右→左も同じ行列で済む。
- 点 (−0.9, y) を (+0.9, y) へ写す。

各 ST の Y 平行移動量:

| ST | Y [m] | 2y [m] | v06 での扱い |
|---|---|---|---|
| ST1 | −1.700 | **−3.400** | `build_op030_stagger_static_v06.py` の `baseline` として**既に計算済み** |
| ST2 | +0.600 | **+1.200** | `delta` として**実施済み**（B を +X へ移設） |
| ST3 | +2.900 | **+5.800** | 新規 |

ST 間隔は 2.300 m。

**注意**: M(y) は Z を変えない。床面が場所によって異なる場合、鏡映しただけでは接地しない（§3.1、§7.2）。

## 3. 6 セルの構成と既存資産の再利用

| セル | 位置 [m] | 由来 | 担当 |
|---|---|---|---|
| S1L | (−0.900, −1.700, 0) | **現行 A をそのまま** | T01 設置＋M4×2、引出し・戻し |
| S1R | (+0.900, −1.700, 0) | **A を M(−1.7) で複製** | T02 設置＋M4×2 |
| S2L | (−0.900, +0.600, 0) | **B を M(+0.6) で複製**（由来は §3.1 で保留） | H03-2 の設置 |
| S2R | (+0.900, +0.600, 0) | **現行 v06 の B をそのまま** | H03-1 の設置 |
| S3L | (−0.900, +2.900, 0) | **現行 C をそのまま** | H03-2 の端子締結 |
| S3R | (+0.900, +2.900, 0) | **C を M(+2.9) で複製** | H03-1 の端子締結 |

**新規に作るのは S1R・S2L・S3R の 3 体のみ。** 残る 3 体は現行資産をそのまま使う。

### 3.1 S2L の由来は床面の確認後に決める（保留）

**床面の基準が 2 つあり、33 mm 食い違っている。**

| 系統 | 足の底面 world Z | 根拠 |
|---|---|---|
| A・C のフィーダ（`feeder_stand()`） | **0.000** | `build_op030_split_v03.py:37`。足中心 world Z = 0.007、厚み 14 mm |
| v06 の B 供給台補修 | **−0.033** | `build_op030_stagger_supported_static_v06.py:28` の `FLOOR_Z = −0.033` |

差はちょうど 33 mm、v06 の補修が動かした量と一致する。読み方は 2 通りあり、**S2L の由来が正反対になる。**

- **読み A — 床が場所によって異なる（+X 側が 33 mm 低い）**: v06 の補修は「B が +X 側へ移ったから」必要だった。この場合 S2L は **v05 の B（未補修）**から作り、S1R・S3R には B と同じ補修を施す。
- **読み B — 床は一様に −0.033**: A・C のフィーダは 33 mm 浮いていることになる。ただし C は実測で接地しているため（§7.2）、この読みは C の記録と矛盾する。

**現時点では読み A が有力だが、確定していない。** 床メッシュの上面 Z を各セル位置で読むまで、S2L の由来を確定しない（§9 作業 0）。

初版で「v06 の補修は左右に関係なく必要」と書いたが、**この断定には根拠がない**。撤回する。

## 4. 移設と複製の違い

v06 は roots の parent を新しい EMPTY へ付け替える「**移設**」だった。v07c は「**複製**」であり、次の差分がある。

1. **名前空間**。v06 は「ロボット・関節・端子 UID のラベルを入れ替えず、元の 78 ノードと実形状を維持」する原則を守った。複製ではこれが成立しないため、**新しい接頭辞を与える**（`OP030B_*` → `OP030_S2L_*`）。UID の衝突を避けることが必須。2026-09-11 裁定により `OP030_S1R_*` 形式を採用。
2. **形状データの共有**。`obj.copy()` のみとし、mesh データは複製元と共有する（2026-09-11 裁定）。形状は同一で行列だけが異なるため。片側だけ形状を変える必要が生じた時点で `obj.data.copy()` へ切り替える。
3. **オブジェクト数**。B の移設対象は roots 104 / moved 420 だった。3 体複製すると **約 1,260 オブジェクトが増える**。現行シーンの 9,570 に対して 13% の増加。レンダリング時間とファイルサイズへの影響を見込む。

## 5. 前提作業 — A と C の複製対象集合

v06 は `analysis/op040_stagger_layout_inventory.json` の `B_candidate_exact_selection`（roots 104 / moved 420 / fixed 76）に依存していた。**A と C について同等の厳密集合がまだ存在しない。**

判定基準は v06 と同じ。

| 複製する | 複製しない |
|---|---|
| ロボット本体、腕、指、オンハンドカメラ | 製品、搬送パレット |
| 供給設備（支持部格子パレット／ケーブル供給／ナット供給器） | 位置決め台、ピン、ストッパ、センサ |
| 制御盤、空圧箱、FRL、ホースと支持 | 共通のカバー枠、外部 LED |
| 床基台と足・脚 | コンベアのローラー・フレーム |

集合の検証は v06 と同じ方法による。

- `roots` の親が `moved` に含まれないこと。
- `roots` の `children_recursive` の合計が `moved` と厳密一致すること。
- `moved ∩ fixed = ∅`。

## 6. 動作の扱い（本仕様の核心）

**供給側は剛体再利用、製品側は再計画。** v06 の原則をそのまま適用する。

製品とパレットは回さない（`product_and_pallet_rotation_preserved: true`）。したがって **鏡映したセルの動作は、そのままでは製品上の正しい座へ届かない。**

### 6.1 S1R（T02 担当）

- **再利用できる**: 格子パレットからの取得、持上げ、組付側への旋回、M4 供給器からのボルト取得。これらは供給側で完結し、供給ごと鏡映されるため剛体再利用が成立する。
- **再計画が要る**: T02 の取付座への設置と M4×2 の締結。T02 の座は製品座標上の固定位置であり、鏡映の影響を受けない。

現行 A の bank は T01 と T02 の両方を含む 7,165 フレーム。`op030_support_motion_v05.py` は支持部ごとに `v05_window=number` を付けているため、**window 単位での分離が可能**。

- S1L = window 1（T01）＋ 引出し・戻し・完了
- S1R = window 2（T02）を M(−1.7) で鏡映し、製品側だけ再計画

### 6.2 S3R（H03-1 の端子締結担当）

- **再利用できる**: M6/M14 供給器からのナット装填、工具の搬送高さへの移動。
- **再計画が要る**: 端子座への位置合わせ、締付け、80 mm 軸抜き。

現行 C の bank は 2,430 フレームで、H03-2 → H03-1 の順に処理している。C は進入順序を H03-2 では M14→M6、H03-1 では M6→M14 と変えて工具本体の半回転を省いているため、**分離時にこの位相の連続性を壊さないこと**。

### 6.3 S2L（H03-2 の設置担当）

- **再利用できる**: 10 本並列供給からの両端同時把持、持上げ、旋回しながらの曲げ。
- **再計画が要る**: J1 挿入、T 着座、支持移管、180 mm 同時上昇。

現行 B の bank 3,787 フレームは H03-2 と H03-1 の両方を含む（フェーズ 1–15 と 17–31）。フェーズ 16 の「次の直線ケーブル供給へ旋回」（6.87 秒）は 2 セル化により**不要になる**。

### 6.4 近接区間の扱い

v07b §5.3 のとおり、フェーズ 8–14（J1 挿入・T 着座・支持移管解放、16.00 秒）は 23 mm ピッチの座の上で行われるため、両側同時が成立しない可能性がある。

**v07c では時間差方式を既定とする。** S2L（H03-2）を先行させ、S2R（H03-1）はその近接区間が明けるまで上空で待つ。ST2 = 80.9 秒。ST1 の 111.7 秒が律速であるため、この選択はタクトに影響しない。

完全同時が成立するなら 63.1 秒へ縮むが、**v07c の成立条件ではない**。検証は v07d の前提として別途行う。

## 7. 空圧と床支持

### 7.1 空圧

v06 では、B を +X 側へ移した際に既存の空圧ドロップ `Split_bay_1__source_0782_m0209_p00..03` が新しい旋回経路と接触し、主管に沿って世界 Y = 0.45 → −0.33 m へ **780 mm 移設**した。枝管は右主管の X1.42 / Z2.62 m へ接続している。

複製で 3 体増えるため、**同種の干渉が 3 箇所で発生し得る**。各セルに枝管と φ28×1700 mm 縦管・上端 tee・FRL・2 フィルタ・ゲージの一組（4 メッシュ）が要る。

- 左主管の座標を確認する（右主管は X1.42 / Z2.62 が既知）。
- 新しい 3 体の旋回経路に対し、全姿勢での FCL 照合を行う。v06 は 975 有限姿勢・179 動的メッシュで交差 0 を確認した後、さらに全 3,787 フレームで再確認している。**同じ二段構えを踏襲する。**

### 7.2 床支持 — 確認結果と残る食い違い

**C は接地している（実測）。** `audit/op030_c_front_feeders_v05_completion.json` の `support_interfaces` に、M6・M14 の 4 足すべてについて次の記録がある。

| 下 | 上 | 界面 | 符号付き Z 間隙 |
|---|---|---|---|
| `source_0001_m0001_p00` | `OP030C_feeder_M6_foot_-0.070` | floor top / foot underside | **3.632×10⁻⁸ m** |
| `source_0001_m0001_p00` | `OP030C_feeder_M6_foot_-0.270` | 同上 | 3.632×10⁻⁸ m |
| `source_0001_m0001_p00` | `OP030C_feeder_M14_foot_-0.151` | 同上 | 3.632×10⁻⁸ m |
| `source_0001_m0001_p00` | `OP030C_feeder_M14_foot_-0.351` | 同上 | 3.632×10⁻⁸ m |

XY 重なりは 120×200 mm。**C の複製に床補修は不要。**

**A は同一の造形手続きで作られている。** `build_op030_split_v03.py:190` の `feeder_stand(feeder)` は A・C の区別なく全フィーダへ適用される。`FEEDER_POSITIONS` は A が M4 (−0.73, −2.65, 0.82)、C が M6 (−1.00, −2.65, 0.84)・M14 (−1.00, −0.75, 0.84)。`feeder_stand()` は足中心を world Z = 0.007、厚み 14 mm に置くため、**足の底面は root の高さによらず world Z = 0.000** になる。A の M4 フィーダも C と同じ接地状態にあると判断できる。

ただし A については**実測記録が Git 側にない**。C と同一構造であることからの推定である。

**残る食い違い（§3.1）**: この world Z = 0.000 は、v06 の B 補修が使った `FLOOR_Z = −0.033` と 33 mm 食い違う。**床面が場所によって異なるのか、床メッシュが複数層なのかが確定していない。** 判定には床メッシュ `source_0001_m0001_p00`（および他の床部材）の上面 Z を、6 セルの各 XY 位置で読む必要がある。

この確認は Blender を 1 回起動するだけで済み、**複製を始める前に片付けるべき**である。

## 8. 検証項目

v06 と同じ基準を適用する。

1. **複製集合の厳密性**（§5）。roots / moved / fixed の三条件。
2. **形状の不変**。複製元の world 行列とローカル署名が変化しないこと。v06 は残る 9,150 オブジェクトの world 行列と 7,239 形状のローカル署名が不変であることを確認した。
3. **鏡映の精度**。複製先の world 行列が `M(y) @ 元の world` と一致すること。v06 の許容は 2×10⁻⁶。引出しの 0 / 170 / 340 mm 位置で評価メッシュが一致することも確認する（v06 は 294 メッシュで最大 0.000196 mm）。
4. **接地**。複製した 3 体すべての足の底面が、その XY 位置の床上面と一致すること。C と同じ `support_interfaces` 形式で記録する。
5. **固定側の不変**。製品・パレット・位置決め装置・カバー枠・LED が動いていないこと。
6. **幾何干渉**。6 セル全ての動作対象について、全保存フレームで意図外交差 0。実メッシュで確認する。
7. **供給の独立性**。両側のセルが同時に供給へ進入しても干渉しないこと。ST2 のケーブル供給は **2 組とする**（2026-09-11 裁定）。
8. **空圧の離隔**（§7.1）。
9. **タクト**。保存動作時間と、実機上限へ引き上げた場合の 2 通り。
