# D40 取付上端の逃げ比較 v01

2026-09-14。根拠は保存D40モデル、既存サービス標本の再計算、今回の生成器とBlender出力。
取付上端だけに0.25 mm／0.5 mmの逃げを設けた比較形状を作成した。
採用寸法と物理的な成立を判定する文書ではない。

## 変更した場所

ユーザーが初期値に指定した40 mm後退と、端子・ケーブル根元の接触面を維持した。
黒い元末節、取付穴周囲、根元パッドと支持部、端子側輪郭、4保存姿勢は変更していない。

変更は各側の青いキャリア454頂点のうち、上端4頂点（index 1 / 3 / 9 / 11）のみ。
元末節から計測した取付面座標のv軸に沿って移動させた。面の構成916枚、色、残る450頂点は
完全に保持した。元の上端はv=−14.5 mm付近で、その次の頂点列はねじ穴端のv=−9.5 mm付近。
この間の上端のみを変更し、穴の径やピッチは変えていない。

| 比較形状 | 上端切下げ | 板高さ | 上端〜最寄り穴端の面内寸法 | 取付面の公称面積減少 | 公称体積減少 |
|---|---:|---:|---:|---:|---:|
| R000 元形状 | 0 mm | 31.00 mm | 5.00 mm | 0 mm² | 0 mm³ |
| R025 | 0.25 mm | 30.75 mm | 4.75 mm | 3.5 mm² | 14 mm³ |
| R050 | 0.50 mm | 30.50 mm | 4.50 mm | 7.0 mm² | 28 mm³ |

板幅14 mm、板厚4 mm、元ねじ2本の16 mmピッチは共通。表の穴端は青い比較板の滑らかな
公称φ3 mm穴であり、黒い元末節のφ3.4 mmクリアランス穴と混同しない。
辺から穴までの寸法を必要強度や加工公差の受入値に読み替えない。

0.25 / 0.5 mmは上端の局所変更を観察する比較値。公差、応力、ねじかかり量から決めた製作寸法
ではない。両案の今回の標本結果は同じなので、ここでどちらかを採用したとは扱わない。

## 同じサービス標本での観測

元の開放姿勢で、片側のキャリア・端子側輪郭・根元パッド・根元支持部の4部品を、元取付面の
法線方向へ動かす計算を行った。参考ワーク、取付ねじと位置決めピンは標本対象に含まない。
sceneの行列には移動を設定せず、計算用のworld頂点コピーにだけ移動量を加えた。

0〜12 mmを0.5 mm刻みで各側25標本。1標本は移動4部品×固定14部品の56組。
3形状×2側で合計8,400組を計算。前回と同じBVHTree epsilon=0の三角形表面交差とAABB除外を使用した。

| 比較形状 | −X側：0.5〜12 mmの24標本で交差を検出した標本数 | ＋X側：同左 | 0 mmの検出 |
|---|---:|---:|---|
| R000 元形状 | 9 | 9 | 各側1組、青いキャリア／同じ側の黒い末節 |
| R025 | 0 | 0 | 同上 |
| R050 | 0 | 0 | 同上 |

0 mmも記録に残した。三角形組数はR000が左右310 / 314、R025が254 / 258、R050が253 / 257。
取付面が接する状態の表面交差を削除したり、侵入深さとして分類したりしていない。

元形状の正の移動量で交差したキャリア面は、全標本とも上端4頂点のいずれかに隣接する面だった。
`baseline_nonzero_offset_face_diagnostic`に両側の面indexと移動量を記録した。
これは交差候補面の局所化であり、面全体のAABB幅を実際の侵入深さとみなすものではない。

**有限標本で交差が検出されなかったことは、連続した取外し経路の成立や実機の交換可否を証明しない。**
固体包含、ねじ・ピン、加工ばらつき、締結、負荷時の変形は今回扱っていない。

## 保存と再確認

- 元D40入力SHAは `cd057bf97a032f14ac331b2efa650f449d488837dfaabcbfb0b897b6b5668d56`。
  読み込み前後に照合し、入力ファイルを保存していない。
- R000の全モデルと4姿勢は入力D40と完全一致。GLBも元D40と同じSHA
  `1d60e7e5f71508345f2807f115377a38e30d00463d782268fd510e68891fe9b3`。
- R000のサービス全標本は前回v01と一致。静止表面組もscene名の候補prefixだけを正規化すると一致。
  最初の後処理比較は `D40_*__` と `R000_*__` の名前差でassertしたため、名前だけを正規化して比較した。
  測定値の変更やBlender再実行は行っていない。
- 各案のGLBは22メッシュ、読み直し時の全体境界差は最大約1.49×10⁻⁹ m。
  全体境界だけで局所形状を保証せず、別途4頂点と全未変更頂点・面・姿勢を照合した。
- Blenderは3形状×4姿勢の12シーン、各22メッシュ。保存前後のworld行列、頂点SHA、面SHA、
  個数、表示状態が一致。標本計算の前後も同じsnapshotで一致した。
- 手と参考ワーク、左右の指先、根元部と取付部の表面組は、候補prefixの正規化後に元形状と一致。
  キャリア／元末節の組だけは上端変更で三角形組数が変わるため、そのまま別記録にした。
- 既存の面は削除・修復していない。今回のNumPy / trimesh float64計算で、厳密な面積0の面は
  −X側0枚、＋X側2枚（index 281 / 284）。この集合は3形状で一致した。
  過去段階や別の数値表現での退化面数と同一視せず、製作用の健全なCADと表現しない。

3Dページは逃げ量、交換量、左右、4保存姿勢、ワークと元部品の表示を切替可能。
橙色は上端面。正面図は取付面の穴と切下げの関係を示し、候補切替に追従する。
標本の検出数は計算済み監査JSONから表示している。PC / mobile各39操作で寸法対応、分解方向、
有限座標、表示切替、WebGL描画、ローカルリンクと横はみ出しを確認し、別JSONに収録した。
配布用コードを別の出力先で実行し、3形状の座標JSONとGLB SHA、全計測値の一致を確認した。
nativeは各実行内の読戻し一致を確認し、実行間のBlenderバイナリSHA一致は要求していない。

## 再利用した根拠と範囲

元末節の14×31 mm面、2ねじ16 mmピッチ、中央位置決め穴は、保持している2016年由来のモデルと
[Robotiq 2018年版取扱説明書 p131](https://assets.robotiq.com/website-assets/support_archives/document_en/2F-85_2F-140_Instruction_Manual_PDF_20181130.pdf#page=131)
の対応を前段で計測済み。今回も同じ計測器と設定SHAを利用した。
新しい公式取付仕様として逃げ量を主張していない。異なる2019 TM版の中央M5取付を混用しない。
取付面の計測、GLB出力、Blender保存、サービス標本は既存実装を再利用した。

この比較に必要な変更は孤立した青い取付板だけなので、ロボット機構、制御、IK、接触モデル、
パッド材質・硬さ・力設定の新規実装は行わない。Klauke 6R6圧着前サンプルとφ14線を、
実Ampere採用部品として扱わない。根元支持部とキャリアの接合方法も今回決定していない。

## ファイルと再生成

- `取付上端の逃げ比較_v01.html`：オフライン3Dと寸法図。
- `hand_mount_relief_meshes_v01.json`：3形状と4姿勢の座標。
- `hand_mount_relief_v01.blend`：3形状×4姿勢。静止シーンのみ。
- `hand_mount_relief_R000/R025/R050_v01.glb`：各形状の近接姿勢。
- `hand_mount_relief_observations_v01.json`：4頂点変更と未変更要素、GLB読戻し。
- `hand_mount_relief_native_v01.json`：標本全文、局所面index、静止組、native読戻し。
- `audit/`：実行ログ、表示と再生成の補助観測。
- `inputs/`、`data/`、`scripts/`：SHA固定の入力と再生成コード。

配布フォルダを作業ディレクトリとして、既存のNumPy / trimesh環境とBlender 4.5を使う。
IsaacLab内ではPythonを `./isaaclab.sh -p` で呼ぶ。`NEW_OUTPUT` は未存在の出力先を指定する。

```bash
python scripts/build_hand_mount_relief_v01.py \
  --source inputs/hand_root_clamp_meshes_v03.json \
  --config data/hand_mount_relief_v01.json --directory NEW_OUTPUT
blender --background --python-exit-code 1 \
  --python scripts/save_hand_mount_relief_v01.py -- --directory NEW_OUTPUT
cp 取付上端の逃げ比較_v01.md NEW_OUTPUT/
```

元のv06とD40は不変。腕軌道・動画は生成していない。正式な物理妥当性判定はVaultProtocol V12の
独立レビュー経路による。本資料にはその判定や新しい受入条件を含めない。
