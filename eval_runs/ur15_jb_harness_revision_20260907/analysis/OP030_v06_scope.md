# OP030 v06 千鳥配置・OP040着手の範囲

観測・指示記録: 2026-09-10T16:24:50.096539+09:00

ユーザーはv05納品後、次工程へ進むことを許可し、ロボットの千鳥配置を指定。その後『ケーブル設置のSTのロボットが移動するんだよね？』と対象を確認した。Bだけを反対側へ移すことでOP010−/OP020＋/A−/B＋/C−/OP040＋…の順になる。最新納品v05（native985c7edf11a80f0e1e15ba5176b3040b9d733c30315ae6b732b4c359239afc3d）は不変で保持する。

## 今回の実装境界

1. OP030v06を新規作成し、OP030Bの床基台を(-.9,.6,0)から(+.9,.6,0)mへ移す。正の行列式を持つ180°剛体回転を使い、腕・指・カメラの形状とFKは保持する。
2. B供給パレット・10本のUID・制御盤・空圧箱と支持/ホースを明示対象で移す。反射scale、cell親全体の回転、製品/位置決め装置の巻込みをしない。全体カバー枠・LED・コンベアとA/Cは維持。
3. 製品と搬送パレットは元のworld回転、原点Z884.5/789mm、搬送Yを保持。Bの供給側は剛体再利用候補とし、固定製品への搬送・曲げ・設置・180mm同時上昇・park接続を元IK/FKで再計算する。
4. A/Cの動作bankは保持し、新しいB固定/可動背景との干渉を差分確認。Bは新しい全frameのFK/実メッシュ、UID、ケーブル線長と把持材点、同時刻の両腕/中央本体を確認。省いた幾何を合格扱いにしない。
5. v06の保存native、工程/全景の動画、工程確認書、再生成入力、再生ページ、ZIPまで仕上げる。新B単独の動作とABC受渡しがわかる映像を用意する。v05を上書きしない。
6. OP040は次工程として接続先/部品表を調査する。旧340mm直線と480.176mm保持形状を同一部品として捏造しない。接続表未定義と既存Tスタッドの露出不足を整理し、承認済み製品の接続先を勝手に増やして動画を作らない。まずB千鳥化を完成させる。
7. 外側の青いF01についてユーザーは必要性を質問し、対象を確認した段階。現行F01は車両側自由端の仮受けで、コネクタ抜け止めではないと説明。低いケーブル受けへの置換を提案したが、現時点の作業指示はB千鳥化。F01/外部ハーネスの形状は自動変更しない。

## 過去の失敗と今回の具体的な差分

root guard `OP040 / 千鳥 / staggered`は10findings/2blockers/6lessons。両blockerは同じ`07-Design/00-DESIGN-STATUS-LEDGER.md:72`のC1 planar cable/clip-retention pinに関する記録で、1DOFケーブルが水平千鳥のクリップに残れない既知境界と未許可の基板変更/学習campaignが対象。今回の新しい明示指示は、別の製品検討Blenderモデルにおけるロボット床基台の左右配置変更。pinや動的ケーブル基板、T-ROOTの実験、学習、実機成立判定は実施しない。この差分を記録してからB配置/動画の作業へ進む。全文はaudit/op030_stagger_v06_prior_art.logに保存。

BのH1右指28mmで隣接H2へ干渉した制約は保持し、右20mm開放→180mm離隔→全開を再確認。全体world bake後に親を回して腕が取り残される方法、製品ごと回して接続面を入れ替える方法は使わない。
