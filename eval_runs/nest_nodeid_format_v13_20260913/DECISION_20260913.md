## 問い 2（tool_use 行 807 / 回答 行 808 = 2026-09-13 07:58:08 JST）

問い 1 の選択肢説明にある `^T-[\w-]+$` について、5 体の事前検証で、実態より広く（Python では日本語・`_`・`T--` も通る）validate.sh Layer 7 C2 の抽出と食い違うこと、および CC の草案が置いていた「唯一の機械検査」という前提が誤り（Layer 7 C2 も node ID を抽出する）であることが判明したため、改めて問うた。

**問い:** §1 に書く node_id の正規表現はどれにしますか？（先の選択肢の文面は `^T-[\w-]+$` でした）

- **実態どおり厳密（推奨）** ← **選択**
  - 説明: `^T-[A-Za-z0-9]+(-[A-Za-z0-9]+)*$`。ASCII 英数字の語を `-` 1 個でつなぐ形。`_`・日本語・先頭/末尾/連続の `-` を許さない。既存 254 件・参照値 256 件を 0 件も落とさない。どの道具でも同じ意味で、Layer 7 の抽出とも矛盾しない。script の濾過は変更せず「規則より緩い濾過」と明記
- **ASCII 英数字と -**
  - 説明: `^T-[A-Za-z0-9-]+$`。上と同じく既存 0 件落ち。`T--` や末尾 `-` は許す
- **選んだとおり `^T-[\w-]+$`**
  - 説明: 検査の正規表現をそのまま規則にする。日本語・`_`・`T--` も合法になり、Layer 7 の参照切れ検査がその ID を見落とす。注記にその限界を書く
