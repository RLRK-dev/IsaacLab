## §6 実装契約 (⭐ 作るのは w2:p4 ・本書は形だけ定めます)

1. driver dir に **module 1 個** (例 `ur15_cell_spec.py`)。全 driver は先頭で **そこからのみ** cell 定数を取る。
2. **Tier A** = 可能なら `thread_isaac_lab.configs.task_config` を import。⚠ import が重い/不可なら **生成した写し + 照合 guard**。
   ⛔ **写すだけで guard 無しは不可** (それが今の状態です)。
   ⛔⛔ **guard は行の sha で作らないでください** (⭐ w2:p0 指摘 ・私の初版が誤り): 行 sha が答えるのは「**バイトが動いたか**」だけで、⛔ コメント修正で**偽警報**を出し、⛔ 別の場所での再代入を**素通し**します。⇒ ⭐ **§6.4 の AST pass で SSOT 側の値を評価し、値どうしを比べる。** ⇒ byte-sha は **通知**へ降格 (失敗させない)。
3. **Tier B** = 本 spec の値を module に直書きし、各行に **本 spec の節番号**を付す。
4. **guard** (安い ・run 不要): ⭐ **名前集合は 1 つでなく 3 つ**。driver の module 直下の大文字代入を AST で数え上げ、**どれにも属さない名前が在れば失敗**する。

| 集合 | 中身 | guard の判定 |
| --- | --- | --- |
| **OWNED** | module が供給する量 (Tier A + Tier B) | ⛔ driver が **再定義**したら失敗 |
| **RETIRED** | ⭐ **退役した構成の定数** — `CLIP_H` `GROOVE_W` `CLIP_RISER` ほか p4 の自作クリップ由来 | ⛔ driver が **定義していたら**失敗 (値は問わない) |
| **TIER-C** | run 固有 (§5) | ✅ 自由 |
| *(上記のどれでもない)* | 新しく発明された定数 | ⛔ **失敗** ・spec への追加を促す (§6.5) |

⛔⛔ **なぜ 3 つ必要か (w2:p0 指摘 ・`-240`(1))**: module は物理 10 のうち **9 を所有し、`CLIP_H` を所有しません** (⭐ 私の設計でクリップが権威ある 5 箱に替わり、`CLIP_H` は**退役した形の定数**になったため)。
⇒ ⛔ **所有だけを見る guard は、driver が `CLIP_H = 0.026` を持ち続けても通します** ⇒ ⭐⭐ **発端の定数 (w2:p6 の発見) だけが射程外**になります。
⇒ ⭐ **一般形**: **所有の検査は「私の値を書き換えたか」しか答えられず、「捨てるべきものを持ち続けたか」を原理的に見られません。** ⇒ 退役集合が要ります。
⇒ ⭐⭐ そして **「どれにも属さない ⇒ 失敗」** が本契約の fail-closed 部分です — これが在れば **明日 発明される定数**も捕まります (列挙では追いつきません)。

#### 6.4a ⭐⭐ 適用範囲の決定 (w2:p0 `-248` の 1 決定依頼への回答)

**⛔ p0 の 3 択はどれも採りません。** 実測 (1 driver): 全 module-level 105 (漏れ 0) / UPPER 58 (漏れ 0) / UPPER∧literal 13 (**漏れ 10**)。

- ⛔ **UPPER∧literal は却下** — 漏れ 10 が `Z_SEAT` `CLIP_C1` `CLIP_C2` `CABLE_Z0` = ⭐ **式で書かれた cell 幾何**、つまり **guard が捕まえるべきもの そのもの**です。
- ⛔ **UPPER 限定も採りません** — 漏れ 0 は **今日の 1 driver での実測**であり、⭐ 「cell 定数は大文字」は**規約であって機構ではありません**。⇒ 明日 `clip_h = 0.026` と小文字で書かれたら素通しします。⇒ 私が終日 指摘してきた「想定しなかった場合を見られない述語」と同型です。

> ⭐⭐ **決定: 適用範囲 = module 直下の 全束縛 (105)。⭐ ただし分類は列挙でなく 1 つの規則で行う。**
>
> **判定規則** = 値の式に **所有名から導けない数値リテラル**が在るか。
> - **在る** ⇒ その束縛は **cell を定義している** ⇒ OWNED / RETIRED / TIER-C のいずれかに属さねばならない。⛔ どれでもなければ **失敗**。
> - **無い** (葉が 所有名 ・model/data オブジェクト ・整数添字 のみ) ⇒ ⭐ **DERIVED** (第 4 種) ⇒ **自由** ・spec に宣言させません。

⭐ **これで p0 の第 4 種 (計算束縛 45 = `CABG` `CLAWG` `GIDX` 等 model からの handle) は 規則で自動的に DERIVED に落ちます** — 名前を列挙しません。
⭐ そして `Z_SEAT = TABLE_TOP + CLIP_RISER + 0.030 - CLAW_OFFSET` は **リテラル 0.030 を持つ**ので捕まります (漏れ 10 のうちの 1 つ)。

⚠ **費用について正直に**: ⛔ 105 名を人が貼るのではありません — ⭐ **規則が大半を DERIVED に落とすので、人の判断が要るのは「リテラルを持つ束縛」だけ** (実測 13 + 漏れ 10 = **23 前後**と私は見ます)。⚠ ⛔ **この 23 は私の見積りで、測定ではありません** (p0 は中間案の費用を未測と明記) ⇒ 実装時に実数が出たら本節を差し替えてください。

⚠ **既知の穴 1 つ**: 「整数リテラル」の扱い。`range(3)` や添字の `0`/`1` を cell 定義と誤判定しないための除外が要りますが、⛔ **除外を広げると `CABLE_N = 32` のような整数の cell 量を逃がします。**
⇒ ⭐ 私の線引き: **名前に直接束縛された数値リテラルは常に cell 定義**扱い (`CABLE_N = 32` は捕まる) ・**添字 / `range` / 比較の中の整数は除外**。⇒ ⛔ これが唯一の裁量部分なので、実装で困ったら戻してください。
5. ⛔ **driver が新しい cell 定数を必要としたとき、自分で定義しない** — 本 spec に足す (w2:p4 の brief 規則① と対)。

## §9 裁定① — ケーブルを SSOT の 600 mm にするか (w2:p4 が §7 に従い停止 ・`-225`)

### 9-1 ⭐⭐ 2 つの定数は **別のもの**を符号化しています

| SSOT 定数 | 符号化しているもの | cell 固有か |
| --- | --- | --- |
| `CABLE_SEG_LEN = 0.015` (`:136`) | ⭐ **離散化の細かさ** (何 mm 刻みでケーブルを表すか) | ⛔ **cell 固有ではありません** — 0.030 に cell 側の理由が在りません |
| `CABLE_SEGMENTS = 40` (`:135`) | ⭐ **全長** (逐語コメント "5-clip span 300mm + 150mm margin each end") | ✅ **cell 固有です** — env の cell の寸法 |

⇒ ⛔ **「SSOT に合わせる」を 2 つまとめて適用したのが、この行き詰まりの原因です。**

### 9-2 ⛔ 600 mm にすると何が外れるか (私の実測)

p4 の cell: saddle `REST_X = (-340, -140, +240) mm` ・clip `C1 +150 / C2 +40`。

| 全長 | 範囲 | saddle |
| --- | --- | --- |
| 960 mm (現行) | ±480 | ✅ 3 本とも内 |
| **600 mm** (SSOT) | ±300 | ⛔ **−340 が外** ⇒ **その saddle は何も載せません** |

⇒ ⭐ 全長は cell の寸法と対 — 私の §7 のとおりでした。

### 9-3 ⭐⭐ 裁定 = **刻みだけ採り、本数は導出する**

> ⭐ **`CABLE_SEG_LEN = 0.015` を採る (SSOT)。⛔ `CABLE_SEGMENTS = 40` は採らない。**
> ⭐ **`CABLE_N` は定数でなく導出量**: `N = 必要な全長 / CABLE_SEG_LEN` ⇒ 960 mm の cell なら **N = 64**。

⇒ ⭐ cell 寸法は 1 mm も動かさずに、⭐⭐ **吸着の量子化床が SEG/2 = 15.0 → 7.5 mm に半減**します。

⚠⚠ **ただし無償ではありません (先に書きます)**: 全長を保ったまま刻みを半分にすると **関節が倍**になります (32 → 64) ⇒ ⭐ **同じ長さに対して曲がりやすくなります。** ⛔ 「同じケーブル」ではありません。
⇒ ⭐ ただし向きは **SSOT の離散化へ寄る**側です (banked run が記録された刻みは 15 mm) ⇒ 忠実度としては**改善方向**。
⇒ ⚠ 計算量も 2 倍 (body/joint 数)。

⚠⚠ **費用の 3 件目 — 私が書き落としていました (w2:p11 `-243` 指摘)**: 刻みを変えると**垂れと傾きが変わる** ⇒ ⛔ **帯 12.00 を決めた置き誤差 4 点 (aim L 1.64 / R 1.45 / STEP3 L 2.33 / R 4.89) は持ち越せません。** 置き誤差は「グリッパ + ケーブル + 狙い loop」という**系の性質**であって、ケーブルだけ差し替えても保たれません。⇒ ⭐ **裁定① を実行するなら、帯の 4 点は再測定が要ります** (⛔ 私は §9-3 で「忠実度は改善方向」とだけ書き、この費用を落としていました)。

### 9-5 ⛔⛔ 本節の主張を撤回します (w2:p11 `-250` ・p11 が正)

⛔ **私の 1.45 mm は「計器の誤差」で、帯を食う物理の項ではありませんでした。**
- 私の量 = 半ピッチ吸着 `15.0 × sin(5.55°)` = **1.45 mm** ⇒ ⭐ これは **ケーブル位置の測り方の誤差**です。
- 帯を食う物理の項 = **爪長由来** `11.0 × tan(5.55°)` = **1.07 mm** ⇒ ⭐ **刻みに依りません。**
⇒ ⛔ **ゆえに「裁定① が余裕の成立条件を買う」は偽です。** 刻みを半分にしても 1.07 は動きません。
⇒ ⛔ **私の型 = 測った量に、それが測っていない結論をぶら下げた** (計器の誤差を、物理の余裕の話に使った)。

⭐ **結論だけは理由を替えて残ります**: **6.00 − 4.89 − 1.07 = 0.04 mm** ⇒ ⭐⭐ **現行の傾きでは 余裕は事実上ゼロで、それは どの刻みでも同じ**です。⇒ **手当は刻みでなく 傾き側 (roll の第 2 の仕事) に在ります。**
