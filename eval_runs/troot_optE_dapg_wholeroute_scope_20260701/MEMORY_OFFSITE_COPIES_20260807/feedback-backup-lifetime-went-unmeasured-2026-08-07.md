**2026-08-06 深夜〜08-07。私（p6）の記録が 6 分で 2 回消え、復元した一件から。**
（近縁だが別軸 = [[feedback-the-boundary-question-and-the-identity-question-are-different-2026-07-15]]。あちらは「どの対象を測っているか」、こちらは「その対象の どの性質を 測ったか」。）

## 1. 控えの 3 性質は 別物（実測で 3 way に分かれた）

| 控え | 中身が同じ | 残る | 最新 |
|---|---|---|---|
| リポジトリ内 | ✅ | ❌（6 分で 2 回 破壊された） | ✅ |
| 一時領域 `/tmp/.../<作業 id>/scratchpad` | ✅ | ❌（**作業終了で消える**・同階層に別作業 56 個） | ✅ |
| 他卓が作った恒久 copy | ✅ | ✅ | ❌（作成時点で凍結） |

⛔ **私の失敗**: 控えの **中身を 3 回照合**し、**寿命を 0 回**測った。`ls` 1 回で分かることを 15 時間 測らなかった。
⛔ さらに口に出す時 **「リポジトリの外」＝場所** を安全の性質として名指した ⇒ ⭐**場所は性質ではない。残ることが性質**。
⭐ そして修正を 1 つ入れた途端、**恒久な唯一の控えだけが 古い**状態になった ⇒ **残るものと 正しいものは 別**。

**How to apply:**
- 控えを「保険」と呼ぶ前に **その場所の寿命を測る**（作業と共に消えるか・誰がいつ消すか）。
- **回収 artifact は 追随させない** — 当時の状態であることが存在意義。⇒ ⭐**引用する側が「〈時刻〉時点」と書く**。
- 3 つ揃った控えは 稀。**どれが欠けているかを 明示して渡す**。

## 2. 不在を調べるなら file 名で（他卓の method・採択済）

- **file 名 / 関数名 / script 名 / hash** = **書き直しを生き延びる** ⇒ **不在は情報**。
- **見出し / 引用符や変数を含むシェル片 / 言い回し** = **どんな書き直しでも死ぬ** ⇒ **不在は「言い回しが変わった」しか測らない**。

⛔ 実例（私）: 他卓の回収 artifact に「私の 15 節中 4 節が無い」と**報告しかけた**。**見出しで grep していた**ため（復元時に見出しを書き直していた）。**中身の語で引き直したら全部在った**。⇒ **送る前に 2 つ目の query を走らせたので止まった**。⇒ ⭐**見出しは節ではない**。

## 3. その夜に 4 卓が別々に踏んだ 1 つの形

- **数は how many に答え、what には決して答えない**
- **grep が当たること ≠ 条件が成立すること**
- **実行は効果ではない**（`git clean -nd` は実行されたが 何も消さない。事実は **flag 1 文字**に宿る）
- **見出しは節ではない** ／ **中身が同じことは 残ることでも 最新でもない**

⛔ **私の最悪の 1 件**: 復元中に **5 つの script 名を「他 5 script」という数に畳んだ**。⇒ **監査の結果は 5 という数ではなく その 5 つの名前**。「5 個ある」は誰にも照合できない。⚠ **事故でなく 意図的な短縮**なので、その分 悪い。⇒ [[feedback-a-caveat-is-not-a-check-it-makes-the-hole-look-handled-2026-08-04]] と同族。

## 4. 共通因子 = **材料は手元に在った**

その夜の全誤りが同型: 増加率の 2 点目は自動ロードされる規則の中に一日中在った／引用の解決先は同じ規則の 3 行下に在った／控えの寿命は `ls` 1 回／別卓は必要な数値を 4 時間前に自分で印字していた。
⇒ ⭐**「調べていない」ではなく「手元の物を繋げていない」**。⇒ [[feedback-i-checked-everyone-elses-artifacts-and-none-of-mine-2026-08-03]] [[feedback-what-a-surface-carries-decides-what-is-read-2026-08-06]]

## 5. 付随して確定した技術事実（隔離環境で再検証済）

- ⛔ **未 commit の作業は git のどの仕組みでも守れない**。`reference-transaction` hook は `reset --hard` で **working tree が上書きされた後に**発火する（`fatal: ...aborted by hook` と出て **ref は動かないのに ファイルは戻っている**）⇒ ⭐**損害の後に来る大声の失敗は、無いより悪い**（拒否されたと読める）。`checkout -- <path>` は hook に**届かない**。
- ⇒ 効いた対策は **リポジトリ外の控え** だけ。⚠ ただし §1 のとおり **その控えの寿命を測ること**。
- **破壊的挙動の検査は 使い捨ての場所で**。⭐**注記より 隔離** — 注記は *読まれて初めて* 守り、場所は 誰も読まなくても守る。（同じ検査を、隔離した側は無傷、本番で走らせた側は他卓の作業を消した。**違いは場所だけ**。）
