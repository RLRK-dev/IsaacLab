## 2b. ⛔ 訂正 2026-08-06 16:48:17 JST — 上の 2.4 は「変更頻度」ではない

p6 が同 dir を測って **6.0 本/日**（900 本 ÷ mtime span 149 日）を出し、p18 が両者の差を「**分母の違い**」と説明した。⛔ **分母だけではない。**

| 数 | **分子が何か** | 母集団 |
|---|---|---|
| **2.4** | 直近 14 日に **最後の**変更があった file（34 本） | 最近触られた file **のみ** |
| **6.0** | **生存している全 file**（900 本） | 3 月以降に作られ**現存する**もの全部 |

⇒ **分子も母集団も違う。**（かつ両集合は重なる — 03-10 作成・08-06 変更の file は 900 にも 34 にも入る ⇒ 分割ではない）

### ⛔ そして **どちらも「変更イベント数」ではない**
**mtime は *最後の* 変更しか記録しない。** 5 回変更された file も日付は 1 つ。実測: 900 本の mtime が占める**相異なる日は 108 日**のみ。
⇒ **2.4 も 6.0 も変更イベントの下限**。さらに 6.0 は**削除された file を一切数えない**（作られて消えた file は 900 に現れない）。
⇒ ⛔ **git のコストを決めるのは変更イベント数**であり、**私はそれを測っていない**（mtime では測れない）。

### ⭐ それでも §2 の結論は立つ — **誤差の向きが分かっているから**
両者とも**下限** ⇒ 真の変更頻度は 6.0 より**大きい**側にしかずれない。
仮に 6.0 本/日 が全て別 commit でも **年 ~2,200 commit の小さな text 差分**で、900 本全体の pack が **4.5 MB** であることに対して無視できる。
⇒ ⭐ **「保存コストは論点でない」は、誤差の向きに対して単調に頑健。**「どちらの読みでも結論は同じ」より強い言い方 — **なぜ同じかを言えている。**

⇒ ⭐ **保存コストは論点ではない。** 初期 4.5 MB・以後は 1 日数 KB の text 差分。
⇒ ⛔ **止めていたのはコストではなかった** — 測って初めてそう言える。
