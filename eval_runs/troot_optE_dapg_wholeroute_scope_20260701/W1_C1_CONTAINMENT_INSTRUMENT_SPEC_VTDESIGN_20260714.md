## §0 ⛔ これは何 *ではない* か(最初に読む)

**本 arc の失敗は全て「計器が測れないものを測ったことにした」から起きた。** 本節を読まずに使わないこと。

| ⛔ 測らない | 理由 |
|---|---|
| **捕捉 / trap / form closure** | **籠は存在しない**(§1.3)。真上への引き抜きは幾何的に自由。**原理的に不可能。** |
| **保持(留まるか)** | 瞬間の幾何。保持は *軌跡* が要る(§2.6) |
| **力** | 壁が押し返しているのか、通り抜けているだけかは分からない |
| ⭐**拘束された body の状態** | **eq 拘束が読む点そのものを固定している間、位置は物理の帰結ではない**(§2.0) |

🔒 **本計器は *スクリーニング* である。最終判定は Rs の動画。数値単独で PASS を出さない。**
🔒 **本計器が DC-1(§4)で旧計器と割れなければ、*建てる意味がない*。**

### ✅ 測るもの(これだけ)

> **cable は *チャンネルの中に居る* か / *縁の上* か / *壁の外* か / *riser に触れている* か。**

⚠ **「spacer の *上* に載っている」とは言わない — それは物理的に起こり得ない**(§4.2a)。**起こるのは riser の *側面* への接触。**

⭐ **旧計器はこれらを弁別できない**(§2.1)。**それが計器の存在理由である。**

## §2 仕様 A — C1 収容判定 述語

### §2.0 🔒 HARD PRECONDITION — **拘束された body は報告しない**

`route_executor.py:2832-2845`(%12 実読):
- pin eq = **`mjEQ_CONNECT`**、`obj2id = 0`(world)、`obj1` = `_seat_world` 最近接 body
- **`mjm.eq_data[_pin_eqid, 0:3] = [0,0,0]` — anchor = seat body の *原点***

⇒ ⛔⛔ **拘束が固定する量(seat body の原点)と、計器が読む量(C1 最近接 cable body の world 位置)は *同一物*。**
⇒ ⭐ **pin が ON の間、その body の |dx| / z は「物理の帰結」ではなく「拘束が強制した値」。**

🔒 **∴ 2 層に分ける(%12 refinement 16:3x — v0.2 の「報告拒否」より良い):**

| 層 | 挙動 |
|---|---|
| **計測層** | ✅ **常に出す。** state / `x` / `z` / `support_geom` に加え、**`eq_active` を必須フィールドで併記。** ⇒ ⭐ **診断情報を捨てない。** |
| **判定層** | ⛔ **読む body に active eq があれば `verdict = UNDEFINED` を返す。** ⭐ **PASS に *絶対に* 数えない(fail-loud)。** |

⇒ ⭐⭐ **数値は残る。しかし汚染された数値が PASS を作ることは *機構的に* 不可能。**
⇒ ⭐ **これは `:3692-3696` の失敗(診断は print するが述語は汚染された MIN のまま)の *正確な逆* である。**

⭐ **本 repo 自身の教訓(`route_executor.py:618-622` 逐語):**
> **「That is a CONTRACT, not a MECHANISM: it holds only while every caller remembers. … Fail-loud is now the mechanism.」**

⇒ 🔒 **precondition は *契約* でなく *機構* として実装する。**

### §2.0b 🔒 precondition は **計器ごと** に書く(pB 実測による refinement)

⭐ **pB 実測:同じ「\|dx\|」に *2 つの別量* がある。**

| 計器 | 定義 | pin ON 時の挙動(pB 実測、5163 frame) |
|---|---|---|
| **計器 A** | C1 最近接 **body** の \|dx\| | ⛔ **std 0.008mm = 完全凍結**(腕は動いているのに 8µm)⇒ ⭐ **拘束が読む点を固定 = 実測 CONFIRMED** |
| **計器 B** | y=C1Y での **補間** \|dx\| | ⚠ **std 0.208mm、range [0.02, 0.92]mm = 凍結しない**(connect は **1 body のみ**、隣接 body は自由) |

🔒 **∴ precondition を計器ごとに規定する:**
- **単一 body を読む計器** ⇒ 「**その body** に active eq があれば `verdict = UNDEFINED`」
- ⭐ **補間する計器** ⇒ 🔒 **「補間に寄与する *いずれかの* body に active eq があれば `verdict = UNDEFINED`」**
  ⛔ **単一 body 判定では計器 B を素通りさせる。**
- ⚠ **計器 B は「無拘束の物理測定」として扱えない**(溶接 body に支配される)。**「凍結していない」は「独立である」を意味しない。**

### §2.0a ✅ **env run は拘束されていない**(適用範囲の明確化)

- ⭐ **env(`newton_route_env.py`)には pin eq が *存在しない*** — `eq_active` grep = **0 ヒット**(= B3-α)。
- ⇒ ✅ **腕 A / 腕 D は *拘束なしの実データ*。計器は env run で拒否しない。**
- ⛔ **producer run(`PERCLIP_PIN=1`)のみが拘束される。** ⇒ **producer 由来の control は取れない**(§4.2)。
- ⇒ ⭐ 「較正が原理的に不可能」ではない。**正しくは「*producer* 由来の positive control が取れない」。**

### §2.1 ⛔ 中核設計則 — **スカラー圧縮を禁じる**

旧計器が capture-blind な *機構*:
```python
# route_executor.py:2514 — 6 geom を個別に読み、min で潰す
_c1_floor_z = float(np.min([mjd.geom_xpos[g][2] for g in _clip1g]))
# ⇒ mj_geomDistance(cable, _clip1g) = {5 clip 箱 + spacer} の *最近接* への距離
```
⇒ ⭐ **必要な per-geom 情報は既にパイプラインに在る。新規計測は不要 — *捨てるのをやめる* だけ。**

🔒 **禁止:** `min` / `nearest` / 距離ノルムによる **N→1 圧縮**。
🔒 **必須:** 部品ごとの **符号付き** 相対位置。

### §2.2 🔒 spacer の分離(FATAL-4 の処置)

**C2 の既存法をそのまま C1 へ**(`route_executor.py:3687-3689`):
```
floor_z  = CLIP1_Z + CLIP_FLOAT_Z                                    # ← built model から
wall_g   = [g for g in clip1g if geom_xpos[g].z >= floor_z - 0.001]  # V溝 5 箱
spacer_g = [g for g in clip1g if geom_xpos[g].z <  floor_z - 0.001]  # riser
```

🔒 **containment 述語は `wall_g` のみを使う。spacer を絶対に混ぜない。**
🔒 **`ON_SPACER` は `spacer_g` への接触で定義する。**
⛔ **split を print で終わらせない。DoD(§4)で「述語が split 後の集合を消費している」ことを検定する。**

### §2.3 4 つの leg(閾値は **全て runtime 導出**、ハードコード禁止)

`wall_g` の world 位置 + half-extent から導出:
```
wall_in_L = wallL.x + hx_wall      # 左壁の内面
wall_in_R = wallR.x - hx_wall      # 右壁の内面
base_top  = base.z  + hz_base
wall_top  = wallL.z + hz_wall      # = 840mm (as-executed)
r         = CABLE_RADIUS
```
| leg | 条件 | 意味 | verdict に入るか |
|---|---|---|---|
| **L1** | `x > wall_in_L + r` | 左壁の内側 | ✅ **主** |
| **L2** | `x < wall_in_R - r` | 右壁の内側 | ✅ **主** |
| **L3** | 🔒 **`z > base_top + r − m`** | base の上(**余裕 m 付き**) | ⚠ **CRIT-2 の判定規則による**(下記) |
| **L4** | `z < wall_top - r` | 壁が張る z 帯の中 | ⚠ 同上 |

#### ⛔⛔ CRIT-1 — v0.4 の `L3: z > base_top + r` は **ナイフエッジ**だった

- **溝床に静止した cable の中心 = ちょうど `base_top + r` = 829.0mm。しかも接触は必ず食い込む ⇒ 実際は 829.0 を *下回る*。**
- ⇒ ⛔ **`829.0 > 829.0` は FALSE** ⇒ **完全に着座した cable が `BELOW_BASE` を返す。**
- ⇒ ⛔⛔ **spec 自身の PC-1(dx=0, z=829 ⇒ `IN_CHANNEL` 期待)が、spec 自身の述語で FAIL する。**
- ⇒ ⭐⭐⭐ **§4.1 が「PASS *できない* 壊れた計器」と名指しした当のものを、その 1 節あとで述語に埋め込んでいた。**

#### ⛔⛔⛔ CRIT-2 — **bar が treatment と共に動く(3 度目)**

| 版 | bar | **誰が bar を決めていたか** |
|---|---|---|
| LOCK v2 | 量子化の床 | **計器のノイズ** |
| LOCK v3→v4 | producer 値 | **pin が保持した値** |
| ⛔ **本 spec v0.4** | **z 閾値(床のナイフエッジ)** | ⛔⛔ **treatment(`ke`)自身** |

- **接触の食い込み ∝ 1/`ke`。そして `ke` は【検定対象そのもの】**(腕A 2500 / 腕D 40000 = **16×**)。
- ⇒ ⛔ **幾何学的に同一位置でも、腕D は腕A より *高く* 静止する** ⇒ **床にナイフエッジを置けば、L3 は「D は収容・A は非収容」を *接触の柔らかさだけ* から出力する。**

🔒 **修正(= %12 裁定。p2 の「z を全部外せ」は *行き過ぎ*):**
- ⛔ **z を verdict から全部外すと、verdict = |dx| のみ ⇒ それは v3/v4 で既に殺され、かつ pin 下で FAIL できない計器。戻ってはいけない。**
- ⭐ **z の本来の仕事 = 「縁の上(845)」と「チャンネル内(829)」の弁別 = 16mm 離れている。食い込みでは揺るがない。**
- ⛔ **危険なのは z 全体ではなく【床のナイフエッジ】だけ。**
- 🔒 **∴ bar を食い込み帯の *外* へ出す:`L3: z > base_top + r − m`**(**m ≫ δ_max** かつ **m ≪ 15mm**)

🔒⭐ **判定規則を【測る前に】固定する(事後合理化の禁止):**

| G1 実測の結果 | 帰結 |
|---|---|
| **δ_max < m/10** | ✅ **z を verdict に残す**(交絡は余裕に埋没) |
| **δ_max ≳ m** | ⛔ **z を 腕A vs 腕D の verdict から外し、診断としてのみ報告**(p2 CRIT-2 が全面的に立つ) |

⛔ **δ_max は【推定でなく実測】で決める**(§4.6 G1)。**μm オーダーという推定を根拠にしない。**

⚠ **L4 を「リップより下」と呼ばない**(cage を含意する。§1.3)。**「壁が張る z 帯 [0.825, 0.840] の中」と呼ぶ。**

### §2.5 geom 帰属(状態とは **直交** する別フィールド)⚠ **2 種類に分ける**(FATAL-5)

⛔ **v0.2 は「支持(下から載る)」だけを持っていた。それでは spacer を捉えられない** — **spacer の上面は base に覆われており、上から載ることは物理的に起こり得ない**(§4.2a)。

⭐ **そして riser 側面への接触こそ、旧計器が「C1 に着座」と誤報する当のもの**(`_clip1g` が spacer を含むため)。
