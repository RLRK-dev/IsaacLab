## §3 Q1 — 「下降点(ケーブル)」の定義

### 結論
**ハンド側の狙い点 = コの口の中心 (pad-local z = 32.00)。ピンチ点ではない。**
**ケーブル側の狙い点 = 最寄りケーブルリンクの中心** (収容判定がケーブル**中心**の帯だから)。

### 根拠
1. §1 の支配関係より、**口を狙えば背板も自動的に満たされる**。ピンチ点を狙っても口は満たされない (口 10.00 に対し背板は 18.75 と広く、狙いの情報量が足りない)。
2. 許容は **±1.00 mm** で、Phase A で最も厳しい。⇒ 最も厳しい脚に狙いを合わせる。
3. driver 設計文 `:88-91` 逐語 = "the cable must arrive in the **slot BETWEEN the claws**" と一致。

### 構成 (⚠ ここを外すと 20 mm 級で外れる)
- **x, y = 顎の中心線**から取る。⛔ 爪 4 個の位置平均は使わない (四節リンクが左右非対称 ⇒ p4 実測で最大 **21 mm** 中心線から外れる)。
- **z = 爪 2 枚の中点**から取る (口の中心)。
- ⭐ **評価する姿勢 = 捕捉時に顎が居る姿勢**。現在の開いた姿勢で評価しない (四節リンクで口が約 **13 mm** 動く・p4 実測)。⇒ **1 回の決定的な評価**で足り、反復は要らない。
- ⇒ driver の `seat_point()` の構成 (x,y = 中心線 / z = 口の高さ) は **正しい**。`slot_centre()` の単純平均は **狙いには使わない**。

## §11 追補 2 (2026-07-27 14:39 以降・w2:p4 の code 実読を受けた撤回と、そこから出る設計上の帰結)

### 11-1 ⛔ §4 の根拠のうち「下降でケーブルが 14-26 mm 動く」を撤回する
w2:p4 が自 code を実読: `cable_at()` に渡す x は **STEP 1 で決めた固定値**で以後更新されない。
⇒ ケーブルが x 方向に滑ると **比較対象の link 自体が入れ替わる** ⇒ ⛔ **「移動量」と「同一性の変化」が混ざっている** ⇒ **量として使えない。**
⇒ ⭐ **§8 の感度表の第 1 行 (下降中のケーブル移動 14-26 mm) は無効。** 取り直しが要る。
⭐ **生き残る根拠 (独立)**: 接触 geom が **f1ext** = **爪がケーブルを叩いている** (p4 の接触同定)。⇒ ⭐ **§4 の結論 (下降は鉛直にし、経路で外乱を作らない) は再導出できるが、量は未測**とする。

### 11-2 ⛔ p11 の「スロットが動く」説は落ちた (向きが逆)
説の予測 = ケーブルはスロットの **下** に残る / R の実測 = ケーブルはスロットの **上**。⇒ **根本原因として運ばない。**
⚠ ただし **13.4 mm という量そのもの**は p4 の相対実測として残る (⛔ 向き = フレーム未実測)。

### 11-3 ⭐⭐ 経路の制約 — 終点だけ合わせても足りない (w2:p18 (6) を設計側で受ける)
実装の `slot_after_close` は **閉じ終えた後の位置**を予測して腕を合わせる ⇒ ⭐ **終点は扱うが、閉じる間にスロットが掃く区間は無防備。**
⇒ ⭐ **設計要件を 1 つ足す**: ケーブルは **閉じ動作の全区間**でスロットの内側に居なければならない。終点だけの一致では、途中で爪が掃いて叩く。
⇒ ⚠ **条件つきの帰結 (量が未確定ゆえ conditional)**: **もし**開↔閉でスロットが **13.4 mm** 動き、スロットの高さが **10.00 mm** なら、⇒ ⛔ **開いた姿勢の帯と閉じた姿勢の帯は重ならない** ⇒ ⭐ **全区間で内側に保てる狙い点は存在しない。**
⇒ ⇒ その場合、捕捉は必然的に「閉じる途中でケーブルが相対的にスロットへ入る」形になり、**閉じる間の爪とケーブルの接触は避けられない** ⇒ 設計は「接触を避ける」ではなく **「接触してもケーブルを弾き出さない」**方向で組む必要がある。
⇒ ⭐ **反証の仕方 (新規 run 1 本で足りる)**: 腕を固定して指だけ閉じ、**スロット中心の変位の大きさと向き**を測る。⇒ 変位 < 10.00 mm なら重なる帯が存在し、狙い点は 1 点で足りる。
