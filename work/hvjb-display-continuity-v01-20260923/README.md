# 概略動画の手先表示 — v05への修正記録

2026-09-23。対象は304ノードの概略表示で、実機の関節軌道ではない。
読取対象と旧OP030 v05の区別は`REVIEW_SCOPE.md`に記録した。

## 読み取った不具合

保存行列を隣接サンプルで比較し、同じ場面内の変化を調べた。
カメラ切替と非表示用の座標は分け、手先と軸対称の描画円筒も分けて集計した。
円筒の軸回りの姿勢差をそのままロボット関節の動きとは扱っていない。

- Aのユニット接近と開放：新しい保持用表示と旧表示の境界で位置・開き幅が飛んでいた。
- Bの板への接近と開放：保持時の90度向きと高さを、境界の1フレームで切り替えていた。
- Cの導体への接近：把持開始時に手先を90度切り替えていた。
- Aの最初の部品：部品は表示時刻12.2から上昇し、手先は12.5まで待っていた。

時刻は旧概略描画の時計で、実機タクトではない。動画内の時刻への対応は監査JSONにある。

## 変更

`correct_display.py`は、既存の表示用arm / oriented_hand / sampleを再利用する。
部品が動く前に手先を接近・閉鎖し、支持先への引渡し後は開いて退避する模式表示へ修正した。
Aの開放幅0.78と上昇量0.45は、同じ概略ユニットを扱う既存S08の表示から再利用した。
これらは実物寸法、把持仕様、クリアランスの受入値ではない。

新しいbankは元の配列を複製してから、6区間のA・B・C主担当の表示だけを書き換える。
1,785サンプル中250サンプル、304ノード中22ノードで変更を記録した。
カメラ、表示時計、部品、工具、配線記号、パレット、共用補助とC補助は同一のまま。
別途、動画側でS12の表示範囲だけを広げた。その操作は`camera_framing.json`で区別した。

## 確認した範囲

5つの不連続点で、元の描画は境界へ近づいても差が残ることを確認し、
修正後は境界の前後間隔を縮めると差が小さくなることを回帰確認した。
Aの最初の部品と手先の表示位置差は、修正区間で0.0894003833から浮動小数誤差の範囲へ変わった。
この数値をメートルへ換算していない。

Aのユニット搬送中、Bの板保持中、Cの導体保持中の既存表示は配列比較で一致した。
元bankのSHAは実行前後で一致し、元ファイルを保存し直していない。

これは表示の読戻しである。自由端の実際の保持方法、指先と実物の接触面、干渉、
把持力、締結品質、実機成立の判定は行っていない。正式判定はVaultProtocol V12の独立経路による。
